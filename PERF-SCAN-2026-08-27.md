# Performance / Optimization Scan — 2026-08-27

**Goal:** make npad.ir load faster. Measured on branch `arena/01a041cb-npad-ir` (v2.18.0) after the fix pass, compared against `main` (v2.17.0). All sizes are real file bytes; gzip ≈ what Cloudflare brotli/gzip delivers.

## What this pass already changed (shipped in this branch)

| Metric | Before (main) | After | Δ |
|---|---|---|---|
| **Critical-path JavaScript** (eager module graph) | 594,943 B raw / ~174,283 B gz | **367,408 B raw / ~91,184 B gz** | **−38% raw / −83 KB gz** |
| — of which dictionary + codecs | loaded on every page | 230,947 B moved to **lazy on first use** | — |
| **Service-worker install traffic** (runs on first visit) | ~1,378,129 B | **3,266 B** (2 offline pages) | **−99.8%** |
| Module graph discovery | serialized (fetch→parse→discover × 6 levels) | `modulepreload` on the 6 heaviest modules → parallel from `<head>` | fewer round-trips on cold start |
| Font readiness | only 400 wt preloaded | both 400 + 600 wt preloaded per locale | bold headings render sooner |
| `favicon.ico` | PHP 404 render per new visitor | static file | −1 PHP exec / visitor |

How the JS reduction was done (no behaviour change, 305/305 tests green):

- `wordlist.js` (170 KB, 18.7k-word dictionary) — dynamic `import()` inside `spellcheck.js` on first pass; the public API stays synchronous, nothing is flagged until it lands (~instant on broadband).
- `formats.js` (61 KB Markdown/JSON/DOCX/PDF/RTF codecs) — dynamic `import()` behind `ensureFormats()` in the 8 File-menu/import call sites; failure (offline before first fetch) shows a localized toast.
- `isPlausibleMath` extracted to 1 KB `math-heuristics.js` so `mathblock.js` no longer drags the codecs into the eager graph; `formats.js` re-exports it for API stability.
- `sw.js` precache reduced to the two offline pages: every real asset is runtime-cached (stale-while-revalidate) during the first online load anyway, so the old list was a duplicate ~1.3 MB download per visitor. Asset matching now uses `ignoreSearch`, so `?v=`-cache-busted URLs and their precached/query-less twins are one entry, not two.
- New static test keeps the dictionary lazy forever (fails the build if anyone statically imports `wordlist.js` or re-adds it to the SW precache).

## Remaining opportunities, in order of impact

### 1. Edge-cache the HTML (Cloudflare dashboard — biggest win, no code)
The one external measurement still shows the origin answering in **~3 s** (`server-timing: cfOrigin;dur=3023`) with `cf-cache-status: DYNAMIC`. Until the HTML arrives, nothing else can. Cache Rule for `/` + `/fa/` with a short Edge TTL turns that into ~10–50 ms globally. Purge on deploy. (If TTFB is still slow uncached, ask the host about the Caddy→LiteSpeed double proxy.)

### 2. Split the four remaining feature modules (code, ~40 KB / math, ~29 KB / outline ~12 KB / checklist ~13 KB raw)
They are eager because the editor wires them at startup. Each can become `import()`-on-demand: load when the active note actually contains `<pre><code>`, `<math-*>`, sections or checklists (checked on note switch/import/paste). Saves ~94 KB raw / ~25 KB gz from the cold path for plain notes. Worth doing only if you want the last mile — the win is a third of the dictionary's.

### 3. Trim the 147 KB HTML (optional)
70 font-picker buttons (with inline `style="font-family:…"`) dominate the raw size. Gzip already collapses the repetition (17 KB), so this matters mostly for parser time on low-end phones. Rendering the font list on first open of the picker (from the same data already shipped in `i18n`) would cut roughly 40 KB raw. Low priority.

### 4. Cache-headers
- Consider a short `s-maxage`-style hint? **Not recommended** while origin `no-cache` protects deploy freshness; the Cloudflare Cache Rule (#1) is the correct layer.
- `assets/css/app.css` could get a content-hashed filename (`app.2.18.0.css`) → `max-age=31536000, immutable`, killing one revalidation per visit. Requires touching `asset()` and the SW list; modest gain (304s are cheap). Optional.

### 5. Static 404 short-circuit for asset extensions (operational)
Bots probing `.php`/`.js` paths run the PHP 404 page. A `RewriteRule` sending obvious non-page extensions (`.jpg|.png|.css|.txt`…) to a static 404 body would shave origin work under scanning. Cosmetic unless you see heavy bot traffic.

### Checked and already good (no action)

- **No render-blocking JS** (`type=module`, `defer`; the one inline script is a 466 B pre-paint theme snippet).
- **Fonts**: self-hosted, subset (latin/arabic 400+600 ≈ 96 KB total), `font-display` swap, preloaded with `crossorigin`.
- **Vendor**: Prism/KaTeX lazy by design; Chart.js only on the admin dashboard.
- **Compression**: `.htaccess` enables deflate + brotli for text types; Cloudflare compresses edge→client.
- **Caching**: fonts + vendored bundles `immutable` 1 y; own CSS/JS `must-revalidate`; `sw.js` `no-store` — correct.
- **Images**: essentially none (inline SVG icons); new `og-image.png` (41 KB) is fetched by scrapers, not by visitors.
- **3rd parties**: zero requests leave the origin (CSP `default-src 'self'`).
- **speculation-rules** (prerender) is already injected by Cloudflare.
- **Autosave/first-input**: spell pass debounced 650 ms, dictionary off the cold path, `pagehide` flush unaffected by any of this.

### Bottom line

Shipped in this branch: **critical-path JS −38%, first-visit service-worker traffic −99.8%, ~210 KB wire to interactive** (from ~293 KB + 1.38 MB). The single remaining large lever is the **Cloudflare Cache Rule for the two HTML pages** — that attacks the measured ~3 s origin TTFB and is a 2-minute dashboard change.
