## Verdict

The AI plumbing (proxy, CSP strategy, consent gates, sanitising) is sound. The failures were
**three specific bugs** that combine into exactly the reported symptoms — "the style formatter
doesn't work, and when it works, Apply doesn't work" — plus a handful of dead/inconsistent
wiring around them.

| # | Severity | Finding | Status |
|---|---|---|---|
| 1 | **Critical** | **Apply on a selection silently did nothing.** `<dialog>.close()` hands focus back to the AI menu button — *not the editor* — and `document.execCommand()` is a no-op unless the editor holds focus. The selection apply paths never re-focused or restored the selection. | **Fixed** |
| 2 | **Critical** | **Notes over ~30k characters killed the button with no dialog and no error.** The truncation warning callbacks called `fmtWords()` — a function referenced 8 times but *defined nowhere* — and threw a `ReferenceError` *outside* every try/catch, so Smart Formatting / Tone Rewrite died silently. | **Fixed** |
| 3 | **High** | **Oversized full-note runs destroyed content.** Input was truncated to 30k chars, but the apply path did `selectAll` + insert — replacing the *whole* note with a partial rewrite of its first chunk. Output could also be cut mid-HTML (`max_tokens` cap 4000). | **Fixed** — now refuses with a clear message |
| 4 | **High** | **Proxy 403'd legitimate requests on non-standard ports.** The same-origin fallback compared `parse_url($origin)[host]` (no port) against `HTTP_HOST` (often `host:port`) — every AI call failed on `localhost:8787`, preview hosts, and any port-bearing deployment. | **Fixed** |
| 5 | **Medium** | **php-wasm dev/preview can never reach AI providers** (`file_get_contents` has no outbound network), so the AI features were untestable outside production. | **Fixed** — dev-only Node fetch bridge in `dev-server.mjs` |
| 6 | **Medium** | **Markdown answers made "Smart Formatting" a no-op.** Models replying in Markdown despite the HTML-only prompt produced a plain-text blob preview and a plain-text insert. | **Fixed** — minimal Markdown→HTML conversion (still sanitized) |
| 7 | Low | Truncation callbacks were accepted by 8 call sites but the `cleanInput(raw, limit)` signature ignored them — the "trimmed to N words" warning could never fire. | **Fixed** |
| 8 | Low | Dead code: `hasFeatureAck`/`setFeatureAck`/`KEY_FEAT_ACK` never used; header docblock described a per-feature prompt that doesn't exist; loading spinner could leak on unknown selection actions. | **Removed/guarded** |
| 9 | Low | Smart Title / Tone picker read radio inputs via global `document.querySelector` after dialog close — worked only because dialog DOM lingers. | **Scoped to `#appDialog`** |

## What was verified as *fine*

- `api/ai-proxy.php` security posture: POST-only, method checks, HTTPS-only upstreams
  (localhost exception), private-range blocking, 60 s timeout, 4 MB cap, status forwarding.
- CSP (`connect-src 'self'`) is satisfied by the same-origin proxy design — correct approach.
- Service worker: network-first for JS/CSS, `/api/` never cached — stale-code issues ruled out.
- `sanitize.js` allow-list covers every tag the Smart Format prompt requests; AI checklist
  markup (`ul.checklist > li > input[type=checkbox]`) matches `checklist.js` exactly.
- Language parity EN/FA intact (both files gained `ai.note_too_long`); string map in
  `includes/editor.php` complete; menu `data-action` wiring (`ai-smart-format` etc.) complete;
  admin dashboard panel writes the same `npad:ai-*` keys the app reads.

## Test coverage added

`tests/ai-buttons.test.mjs` (9 checks, wired into `tests/run.mjs`):

1. Smart Format: Apply re-focuses the editor, restores the selection, inserts HTML **with the editor focused** (regression for #1).
2. Tone Rewrite: same, with `insertText` (regression for #1).
3–4. 40k-char full-note runs abort with a message, zero `execCommand` calls — content untouched (#3).
5. Markdown-only reply becomes real `<h3>/<ul>/<strong>` structure in preview and insert (#6).
6. Truncation warning fires for oversized Summarize input (#7).
7–9. Proxy origin rules: Host-with-port accepted, foreign origin 403, plain-HTTP upstream 400 (#4).

Harness hardening in `tests/run.mjs`: async checks are now tracked and awaited before the
tally (previously counted *before they ran*, then killed by `process.exit`); the behaviour
suite awaits its checks before closing its jsdom window. **331 passed, 0 failed** (was 322).

## How to verify by hand

1. Open the editor → AI menu → **AI Settings…** → enter any OpenAI-compatible
   Base URL / API key / model (DeepSeek, OpenAI, Gemini, Groq…) → **Test connection** → **Save settings**.
2. Select a paragraph → **Smart Formatting** → **Apply** — the selection is replaced with
   formatted HTML (this was the broken path).
3. Long note (>30k chars) → Smart Formatting now tells you to select a portion instead of
   silently rewriting only the beginning.
4. Select a word → floating AI toolbar → *Suggest replacements* → click a word — it replaces
   in place (also previously focus-broken).

> Note: under `npm run dev` (php-wasm) the AI proxy is bridged through Node — production
> PHP (cPanel) is untouched and needs `allow_url_fopen`-capable `file_get_contents`, which
> shared hosts provide by default.
