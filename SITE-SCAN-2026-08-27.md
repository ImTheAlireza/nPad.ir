# SECURITY

## S1 · Admin login has no brute-force protection — **Medium**
`admin/dashboard.php:106-121`. The login is a single shared password behind a public URL (confirmed live: `/admin/dashboard.php` renders the sign-in form to anyone). A CSRF token is required (good) and a failed attempt sleeps 400 ms — but there is **no attempt counter, lockout, captcha, or rate limit**. That permits ~2.5 guesses/second/IP sustained (~200k/day). The admin page exposes truncated IPs and user agents (low-value data), but analytics integrity is worth protecting.
**Fix:** reuse the file-based fixed-window limiter from `api/track.php` keyed on `REMOTE_ADDR` (e.g. 5 failed logins/10 min → 429), and/or restrict `/admin/` to your IP in `.htaccess`, and/or put it behind fail2ban.

## S2 · Logout is a GET link — **Low**
`admin/dashboard.php:71-76` (`?logout`). Any external page can embed `<img src="https://npad.ir/admin/dashboard.php?logout">` and silently sign the admin out (CSRF logout). Cheap fix: make logout a POST with the CSRF token.

## S3 · CSP still carries `script-src 'unsafe-inline'` — **Low (hardening)**
`.htaccess` CSP (verified live by securityheaders.com, grade A with warning). The only inline script is the pre-paint theme snippet in `includes/head.php`. Its content is static, so pin it with a **SHA-256 hash** (or move it to a tiny blocking external file) and drop `'unsafe-inline'` from `script-src`. `style-src 'unsafe-inline'` is still needed (inline `style=` attributes in admin/dashboard markup), acceptable.

## S4 · `X-Forwarded-Proto` is trusted in the HTTPS redirect — **Low**
`.htaccess`: `RewriteCond %{HTTPS} off` + `RewriteCond %{HTTP:X-Forwarded-Proto} !https` → redirect. The header is client-controlled; anyone who reaches the origin directly over HTTP with `X-Forwarded-Proto: https` skips the redirect and gets plain-HTTP responses. This only matters if the origin IP leaks — and it partially does (see S6: `via: 2.0 Caddy`, `x-turbo-charged-by: LiteSpeed` headers). Recommended: at the host firewall allow only Cloudflare IP ranges to 80/443, then the condition is safe; Cloudflare's "Always Use HTTPS" (already active — the edge issued the 301 in testing) is the outer layer anyway.

## S5 · Behind Cloudflare, `REMOTE_ADDR` may be the edge IP — **Medium (verify)**
`api/track.php` deliberately uses `REMOTE_ADDR` only (correct stance against header spoofing) — but the site is proxied by Cloudflare. Unless the host restores the real client IP (LiteSpeed `mod_remoteip` equivalent / Cloudflare Apache module), three things break:
1. the 60 req/min rate limit becomes **shared across every visitor per edge IP** → self-DoS at modest traffic;
2. analytics "unique visitors" counts Cloudflare POPs, not people (the IP truncation would be anonymizing Cloudflare, not users);
3. the admin dashboard's "Your IP" shows an edge IP.
**Verify on the host** that the real client IP is restored into `REMOTE_ADDR` before this is a non-issue. (The host WAF did see a real client IP in its block page, which suggests *something* restores it — confirm it applies to PHP too.)

## S6 · Dev/test tooling is deployed and web-accessible — **Low**
Confirmed live: `https://npad.ir/dev-server.mjs` serves the full dev-server source (fetched end-to-end). `tests/` returns 403 (rewrite rule), `package.json`/`*.md`/dotfiles 403 — but `dev-server.mjs`, `runone.mjs`, and any stray files (e.g. `node_modules/` if present at deploy time, see O4) are not covered.
**Fix:** extend the deny `FilesMatch` with `dev-server\.mjs|runone\.mjs|composer\..*|.*\.mjs$` (or at least the two), and exclude dev files from the cPanel deploy (O4).

## S7 · Rate-limit temp files accumulate forever — **Low**
`api/track.php:143-170` creates `/tmp/npad_rate_<sha>` per IP per minute and never unlinks old files. Every unique visitor-minute = one file, kept until the host's tmp cleaner (if any) runs. On a busy month this is thousands of small files/inodes. **Fix:** unlink files older than the current window when writing (cheap opportunistic `glob` cleanup), or keep the counter in APCu/the analytics DB.

## S8 · `track.php` same-origin fallback can be bypassed by old clients — **Low**
If `Sec-Fetch-Site` is absent *and* no `Origin`/`Referer` is sent (older browsers/extensions), a cross-site POST is accepted. Impact is bounded (allow-listed event names + IP rate limit) — worst case is log spam / stats pollution. Optionally reject when all three headers are missing.

## S9 · Session hardening gaps (admin) — **Low**
- No absolute session lifetime: idle expiry (30 min default) exists, but `login_time` is stored and never enforced — an actively-used session lives forever.
- `session.cookie_secure` is set at runtime only when `$_SERVER['HTTPS']` is on (`dashboard.php:44`); if the origin terminates TLS at Cloudflare and speaks HTTP to Apache, the runtime flag is skipped. The `.user.ini` sets it unconditionally — **but `.user.ini` only applies to PHP-FPM; verify the host actually honors it** (it is web-blocked, which is correct).

## S10 · Minor / informational
- HSTS present (`max-age=31536000; includeSubDomains`, verified live) — `preload` not enabled (optional).
- `Cross-Origin-Resource-Policy`/`Cross-Origin-Embedder-Policy` not set (optional, "upcoming" headers).
- Stack disclosure headers from the host: `via: 2.0 Caddy`, `x-turbo-charged-by: LiteSpeed` (host-level, hide if possible).
- `package-lock.json` is git-ignored → dev tooling versions aren't pinned (dev-only reproducibility).
- The host WAF block page (Persian, reCAPTCHA) is aggressive — desirable, but make sure it whitelists beacon POSTs to `/api/track.php` (plain form-data, low keyword risk today).

## Verified good (no action)
- **Sensitive paths blocked live:** `/config.php`, `/package.json`, `/includes/bootstrap.php`, `/tests/run.mjs`, `*.md`, dotfiles → 403. Sitemap/robots/404/fa routes all correct.
- **securityheaders.com: A.** CSP, HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, COOP all present; `frame-ancestors 'none'` replaces XFO; `X-Powered-By` unset.
- **SQL:** every statement prepared/parameterized; the date filter is a fixed literal chosen from an allow-list. CSV export neutralizes formula injection (`csvSafe`).
- **Client sanitizer** (`sanitize.js`): removes `script/style/iframe/object/embed/link/meta/form/button/svg/math`; URL scheme allow-list (`javascript:`/`data:` dropped); `url()`/`expression()` stripped from styles; table spans bounded (≤100); checkbox inputs confined to checklists; `target=_blank` gets `rel="noopener noreferrer"`. Restored/pasted/imported HTML all pass through it. Link dialog rejects non-`http(s)`.
- **No secrets in git history**; `config.php`/`.env` ignored; no server-side file uploads.
- Import bounds: 25 MB per file; DOCX decompression capped at 30 MB and 10 000 entries (zip-bomb safe).
- DNT/GPC honored client- and server-side; IPs truncated (IPv4 last octet / IPv6 beyond /48) before storage; privacy page matches actual behavior.

# OPERATIONAL / PERFORMANCE

## O1 · Origin TTFB measured ≈ 3 seconds (single sample) — **High priority to verify**
The external header scan captured `server-timing: cfEdge;dur=13, cfOrigin;dur=3023` for the homepage — the edge was fast but the **origin took ~3.0 s**. `cf-cache-status: DYNAMIC` means HTML is never cached at the edge, so every first-time visitor may pay this. The chain is Cloudflare → Caddy → LiteSpeed → PHP; a 3 s origin delay on a small PHP page suggests shared-hosting cold starts, WAF inspection, or geographic distance.
**Fix:** (a) measure TTFB from a few regions over a day; (b) add a Cloudflare **Cache Rule** for `/` and `/fa/` with a short Edge TTL (e.g. 5 min) + purge on deploy, or enable APO; the pages are identical for everyone, so edge caching is safe; (c) ask the host about the Caddy→LiteSpeed hop.

## O2 · `/favicon.ico` 404s through the full PHP error document — **Low**
Confirmed live: browsers' automatic `/favicon.ico` request (and any bot's) executes `404.php` — bootstrap, lang load, full page render — for a favicon that never existed. **Fix:** ship a real static `favicon.ico` (or a one-line rewrite to `favicon.svg`).

## O3 · Deploy resets every `lastmod`/"Updated" date — **Low**
`sitemap.php` and `privacy.php` derive dates from `filemtime()`, so any deploy — even of unrelated files — stamps all URLs "modified today" (live: all four `lastmod` = 2026-08-27, privacy "Updated: 2026-08-27"). Google learns to distrust uniformly-fresh dates. **Fix:** derive `lastmod` from the last commit that touched the page's files (a tiny deploy-time script), or drop `lastmod` entirely.

## O4 · cPanel deploy copies dev/tooling files into `public_html` — **Medium (hygiene)**
`.cpanel.yml` runs `cp -R *`, which copies **everything non-dot**: `tests/`, `dev-server.mjs`, `runone.mjs`, `AUDIT.md`-style docs, and — if `npm install` was ever run locally — the entire `node_modules/` tree (thousands of files, slow deploys, wasted disk, broader web surface). `.htaccess` blocks `tests/`, `*.md`, `package*.json`, but not `*.mjs` or `node_modules` (see S6).
**Fix:** in `.cpanel.yml`, copy an explicit allow-list (`assets css fonts includes lang api admin *.php *.html *.svg *.png *.webmanifest sw.js robots.txt .htaccess .user.ini`) instead of `*`.

## O5 · Service-worker precache double-stores the two entry files — **Low**
The HTML references `/assets/css/app.css?v=<mtime>` and `/assets/js/app.js?v=<mtime>`, but `sw.js` precaches the query-less URLs. `caches.match()` compares the full URL including `?v=`, so the precached entries can **never** satisfy those requests — they're pure duplicate storage while runtime SWR caching does the real work. Either pass `{ ignoreSearch: true }` when matching assets, or precache the versioned URLs. (Vendor files and ES-module imports are query-less, so they're fine.) Also note the install-time precache downloads ~1 MB including Prism+KaTeX+wordlist for every visitor.

## O6 · First-load JavaScript is ~600 KB raw, eagerly imported — **Medium (perf)**
`app.js` → `editor.js` statically imports everything: `wordlist.js` is **170 KB** (bundled en/fa dictionary) and `formats.js` is 61 KB; both are needed only when the user types a first misspelling or first imports/exports. Dynamically `import()` the wordlist on the first spell pass and `formats.js` on first File-menu use to cut first-load JS roughly in half (gzip softens it today, but parse time on low-end phones doesn't care). The 600-weight fonts aren't preloaded either (only 400 is).

## O7 · No CI workflow — **Low**
The test suite is excellent (301 checks, incl. contrast/a11y/sanitizer) but nothing runs it automatically. Add a GitHub Actions workflow (`npm ci && npm test` — note: un-ignore `package-lock.json` so `npm ci` works) on every PR.

# UX

## U1 · Browser tab / SERP title becomes "Untitled note — NPad" — **Medium (SEO-visible)**
`editor.js:3895-3901`: on load, `updateDocumentTitle()` runs with the note's default title ("Untitled note" / "یادداشت بدون عنوان"), which is truthy → it replaces the marketing `<title>` ("NPad — Free Online Notepad with Auto-Save"). **Confirmed live on both `/` and `/fa/`** (fetched titles: `⁧Untitled note⁩ — NPad`, `⁧یادداشت بدون عنوان⁩ — NPad`). Consequences: useless tab labels and bookmark names for everyone who hasn't named a note, and Google (which renders JS) may index that as the page title. The FSI/PDI isolate characters (`⁧…⁩`) would even appear in the SERP snippet.
**Fix:** only override `document.title` when the title differs from the default `strings.noteUntitled` (empty-or-default → keep `initialDocumentTitle`).

## U2 · Skip link points at `#editor` on pages with no editor — **Low (a11y)**
`includes/head.php:90` always renders "Skip to editor". On `privacy.php`, `fa/privacy.php` and the 404 page there is no `#editor` (confirmed live: the skip link on the 404 page is `.../favicon.ico#editor`). Keyboard users activate it and nothing happens. **Fix:** let pages pass their own skip target (e.g. `#main`) or omit the link.

## U3 · `offline.html` is English-only — **Low**
A Persian visitor who loses connectivity gets an English-only offline screen (`/fa/` falls back to `/offline.html` in `sw.js`). Add a localized `offline.html` per locale (or one bilingual page) and match it on `url.pathname`.

## U4 · Every link the user creates is forced to open in a new tab — **Low**
`editor.js:2724-2728` sets `target="_blank"` (with `rel="noopener noreferrer"`) on all created links, with no choice. In-note links opening in the same tab is a legitimate expectation; consider a checkbox in the link dialog, or follow the existing anchor only.

## U5 · Small consistency nits
- `site.webmanifest` `theme_color` is `#0e7490` while the page meta is `#eef1f5`/`#0b1120` → installed-app chrome won't match the site theme. The PNGs declare `purpose: "any maskable"` — serving one file for both is discouraged (maskable icons need safe-zone padding); split or drop `maskable`.
- Font preload covers only the 400 weight; headings/toolbar (600) fetch later.
- Ctrl+S is "export TXT" rather than "save" (documented in the shortcut table, so intentional — but new users may expect a save dialog; a one-time toast explaining where notes are saved could preempt "did I lose my work?" confusion).

## Verified good (no action)
- Autosave with dirty-tracking, `pagehide`/`visibilitychange` synchronous flush (closing the tab within the debounce does **not** lose work — tested).
- Bounded, local backups (30/note, 120 total) that snapshot before deletes; restore creates a separate note.
- Menus are keyboard-operable (aria-expanded, arrows, Escape); dialogs are native `<dialog>` with focus trap; toasts are in an aria-live region; skip link, `:focus-visible` styles, print/reduced-motion/forced-colors media blocks all present; coarse-pointer targets sized up; WCAG-AA contrast is enforced by tests in both themes.
- Offline flow works (network-first navigation with cached-shell + offline fallback); `/api/` and `/admin/` correctly bypass the SW cache.

# SEO

- **E1 (=U1):** JS title overwrite is the one real defect — Google renders JS, and the rendered title is "Untitled note".
- **E2:** No `og:image`/`twitter:image` — `twitter:card=summary` and OG tags exist but link previews render imageless. Add a 1200×630 og image (can be a simple branded card).
- **E3 (=O3):** `lastmod` uniformity on every deploy.
- Everything else checked out live: canonical + `hreflang` (en/fa/x-default) on every page including the sitemap, valid sitemap with only real URLs, robots.txt correct and no longer advertising dead paths, `noindex` on admin, 404 page returns proper 404 with locale awareness, www→apex redirect works, single `<h1>` per page, FAQ structured data mirrors on-page content, no fabricated ratings.
